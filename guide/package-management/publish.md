# vp pm publish {#vp-pm-publish}

Публикует пакет в реестре. Поддерживаемые цели и параметры предварительного просмотра зависят от менеджера пакетов:

```bash
vp pm publish --dry-run
vp pm publish --access public --tag next
vp pm publish ./package.tgz
```

## Параметры {#options}

| Параметр                        | Описание                                                | Примечания                              |
| ------------------------------- | ------------------------------------------------------- | --------------------------------------- |
| `--dry-run`                     | Выполняет предварительный просмотр без публикации.      |                                         |
| `--tag <tag>`                   | Выбирает dist-тег.                                      |                                         |
| `--access <public\|restricted>` | Запрашивает публичный или ограниченный доступ к пакету. |                                         |
| `--otp <otp>`                   | Указывает одноразовый пароль.                           |                                         |
| `--no-git-checks`               | Пропускает проверки git.                                |                                         |
| `--publish-branch <branch>`     | Задаёт имя ветки, из которой выполняется публикация.    |                                         |
| `--report-summary`              | Сохраняет сводку публикации.                            |                                         |
| `--provenance`                  | Публикует с атрибуцией происхождения (provenance).      | Требуется совместимая среда публикации. |
| `--force`                       | Запрашивает нативную принудительную публикацию.         |                                         |
| `--json`                        | Запрашивает нативный вывод в формате JSON.              | Вывод сохраняет нативную схему.         |
| `-r, --recursive`               | Публикует все пакеты рабочего пространства.             |                                         |
| `--filter <pattern>`            | Выбирает рабочие пространства по шаблону.               | Можно указывать несколько раз.          |

## Совместимость {#compatibility}

- **npm:** `npm publish`.
- **pnpm:** `pnpm publish`.
- **Yarn Classic:** `yarn publish`.
- **Yarn Modern:** `yarn npm publish` для активного рабочего пространства. Явные цели в виде tarball-архива или каталога отклоняются.
- **Bun:** `bun publish`.

| ------------------------------- | ---------------- | ---------------------------- | ---------------- | --------------- | --- | ---------- |
| `--dry-run`                     | 5.10.0 или новее | Да                           | Нет              | 4.9.3 или новее | Да  |            |
| `--tag <tag>`                   | Да               | Да                           | Да               | Да              | Да  |            |
| `--access <public\|restricted>` | Да               | Да                           | Да               | Да              | Да  |            |
| `--otp <otp>`                   | Да               | Да                           | 1.12.1 или новее | 3.2.0 или новее | Да  |            |
| `--no-git-checks`               | Нет              | Да                           | Нет              | Нет             | Нет |            |
| `--publish-branch <branch>`     | Нет              | Да                           | Нет              | Нет             | Нет |            |
| `--report-summary`              | Нет              | Да                           | Нет              | Нет             | Нет |            |
| `--provenance`                  | 9.5.0 или новее  | Да                           | Нет              | 4.9.0 или новее | Нет |            |

Публикация Yarn использует конфигурацию реестра и учётные данные Yarn. Неподдерживаемые цели и выбор рабочего пространства приводят к ошибке, а не к переходу на npm. Сбои нативной публикации не повторяются через npm.

Vite+ отклоняет неподдерживаемые параметры до запуска нативной команды публикации. Yarn Classic может проигнорировать `--dry-run` и выполнить настоящую публикацию либо принять `--provenance` без создания аттестации. Vite+ отклоняет оба параметра для Yarn Classic.

Аргументы после `--` передаются напрямую нативной команде без этих проверок. Передача неподдерживаемого параметра безопасности таким способом может привести к настоящей публикации или к публикации без атрибуции происхождения.

Для сценария, разделяющего загрузку в CI и одобрение сопровождающим, используйте [stage](./stage).
