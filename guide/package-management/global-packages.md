# Глобальные пакеты {#global-packages}

Операции с глобальными пакетами требуют [глобального CLI](/guide/global-cli). Используйте `-g`, чтобы управлять инструментами независимо от зависимостей проекта:

```bash
vp install -g typescript
vp install -g --node 22 typescript
vp uninstall -g typescript
vp update -g
vp list -g
vp outdated -g
```

## Хранилище и Node.js {#storage-and-node-js}

Vite+ хранит глобальные пакеты в `packages/` внутри разрешённого каталога данных, а не в глобальном каталоге установки базового менеджера пакетов.

Без `--node` глобальная установка использует версию Node.js, определённую для текущего каталога. Поэтому закрепление версии проекта имеет приоритет над `vp env default`. См. [Выбор версии Node.js](/guide/env#node-js-selection).

`vp link` использует нативные ссылки менеджера пакетов. Команда не изменяет глобальное хранилище пакетов Vite+, и такие ссылки не отображаются в `vp list -g`.

## Обновление пакетов {#updating-packages}

Обновления сохраняют спецификацию версии, зафиксированную при установке. Пакет, установленный как `some-pkg@nightly`, обновляется до последней версии этого тега. Диапазон версий остаётся в пределах диапазона.

```bash
vp update -g some-pkg
vp update -g some-pkg@latest
vp update -g --latest
```

С `--latest` дальнейшие обновления следуют за тегом `latest` вместо исходного тега или диапазона версий.
