# Tap Homebrew {#homebrew-tap}

Официальный tap (репозиторий формул Homebrew) поддерживает macOS и glibc Linux на ARM64 и x64. Homebrew управляет нативным исполняемым файлом `vp`, а `vp` — своими JavaScript-зависимостями, загруженными версиями Node.js, менеджерами пакетов и настройками в пользовательских каталогах.
Стабильная установка загружает исполняемый файл и его lock-файл зависимостей из GitHub Releases. Этот шаг не требует установленного Node.js или менеджера пакетов, а также доступа к реестру npm.

## Установка {#install}

Установите tap:

```bash
brew tap voidzero-dev/vite-plus https://github.com/voidzero-dev/vite-plus
brew install voidzero-dev/vite-plus/vp
vp
```

Явный URL репозитория обязателен, потому что формула является частью репозитория Vite+.
Если вы уже используете Vite+, следуйте [шагам миграции](#switch-an-existing-installation).

## Первое использование {#first-use}

При первом использовании `vp` устанавливает подходящие зависимости CLI и настраивает вашу оболочку и параметры управления инструментами. Этот шаг требует доступа к загрузкам Node.js и к вашему реестру npm.
Настройка использует закреплённые версии Node.js и pnpm из выпуска, даже если вы предпочитаете системные инструменты. Совместимый [`VP_SETUP_NODE_VERSION`](/guide/global-cli#vp-setup-node-version) может переопределить рантайм установки, не изменяя выбор Node.js для ваших проектов.
`vp` хранит зависимости в `<DATA>/cli-packages/<version>/<platform>`.
`<DATA>` берётся из [конфигурации каталогов Vite+](/guide/global-cli#installation-variables).

После настройки откройте новый терминал, чтобы шимы стали доступны в `PATH`. Последующие запуски используют уже выполненную настройку.
Используйте [`vp env on` и `vp env off`](/guide/env), чтобы изменить набор инструментов, которыми управляет `vp`.

## Пользовательский реестр npm {#custom-npm-registry}

Настройка при первом запуске читает `~/.npmrc`, включая совместимую с npm аутентификацию:

```ini
registry=https://registry.example.com/repository/npm/
//registry.example.com/repository/npm/:_authToken=${NPM_TOKEN}
```

Экспортируйте `NPM_TOKEN` перед запуском `vp`. И встроенный загрузчик pnpm, и установка зависимостей через pnpm используют эту конфигурацию.
Вы можете выбрать другой файл через `NPM_CONFIG_USERCONFIG` или переопределить реестр через `NPM_CONFIG_REGISTRY`.
Относительные пути пользовательской конфигурации разрешаются от текущего каталога. Переменные npm, специфичные для Homebrew, не требуются.

Ошибки аутентификации останавливают настройку. Исправьте конфигурацию и снова запустите `vp`; настройка сохраняет ваш выбор управления.

## Восстановление после неудачной настройки {#recover-from-failed-setup}

Выполните `vp env doctor`, чтобы проверить исполняемый файл, каталог зависимостей и шимы. Его проверка зависимостей CLI читает локальные файлы и не устанавливает и не восстанавливает зависимости. Другие проверки могут получать метаданные версий Node.js.

Исправьте указанную проблему с конфигурацией, доступом или местом на диске, затем выполните `vp --help`, чтобы повторить настройку.
При ошибке с lock-файлом работает и [вариант восстановления установщика](/guide/global-cli#vp-setup-skip-install-lockfile):

```bash
VP_SETUP_SKIP_INSTALL_LOCKFILE=1 vp --help
```

Так зависимости разрешаются без опубликованного lock-файла. Последующий запуск без этого переопределения восстанавливает обычные проверки lock-файла и может заново установить эти зависимости.
Если pnpm завершается с ошибкой, в выводимом журнале есть его код выхода и распознанные коды ошибок, но нет исходного вывода менеджера пакетов.
Настроенные шимы инструментов могут запускать кэшированные Node.js, менеджеры пакетов и глобальные пакеты независимо от восстановления зависимостей CLI.

## Переход на tap с существующей установкой {#switch-an-existing-installation}

Сохраните существующие настройки каталогов. Миграция сохраняет ваши предпочтения, рантаймы и глобальные пакеты и обновляет их шимы, чтобы они указывали на общедоступную команду `vp` из Homebrew.
Не запускайте `vp implode`: он удаляет эти пользовательские данные. После перехода откройте новый терминал.

### Переход со скриптовой установки {#switch-from-the-script-installer}

Выполните приведённые выше команды `brew tap` и `brew install`. Затем вызовите исполняемый файл Homebrew напрямую, чтобы существующий шим скриптовой установки не получил приоритет:

```bash
"$(brew --prefix)/bin/vp" env setup --refresh
```

### Переход с Homebrew Core {#switch-from-homebrew-core}

Формула `vite-plus` предоставляет те же команды, поэтому её нужно удалить перед установкой tap:

```bash
brew tap voidzero-dev/vite-plus https://github.com/voidzero-dev/vite-plus
brew uninstall vite-plus
brew install voidzero-dev/vite-plus/vp
"$(brew --prefix)/bin/vp" env setup --refresh
```

## Обновление и удаление {#upgrade-or-remove}

```bash
brew upgrade voidzero-dev/vite-plus/vp
```

После обновления выполните `vp`, чтобы подготовить подходящие зависимости. Настройка сохраняет ваши предпочтения.
`vp upgrade` определяет официальный tap и направляет вас к `brew upgrade voidzero-dev/vite-plus/vp`.

Для полного удаления сначала удалите пользовательские данные, а затем удалите исполняемый файл:

```bash
vp implode
brew uninstall voidzero-dev/vite-plus/vp
```

Один только `brew uninstall` сохраняет пользовательские данные. На общей машине каждая учётная запись операционной системы может удалить свои данные с помощью `vp implode` до удаления исполняемого файла.

## Проверка предварительной сборки {#test-a-preview-build}

Задайте `HOMEBREW_VP_PR_VERSION` номером PR или полным SHA коммита. В PR должен быть опубликован `preview-build` с поддержкой tap Homebrew. Используйте полный SHA, чтобы установка и проверка шли по одному и тому же коммиту:

```bash
brew tap voidzero-dev/vite-plus https://github.com/voidzero-dev/vite-plus
HOMEBREW_VP_PR_VERSION="<full-commit-sha>" brew install voidzero-dev/vite-plus/vp
HOMEBREW_VP_PR_VERSION="<full-commit-sha>" brew test voidzero-dev/vite-plus/vp
```

Используйте `brew reinstall` вместо `brew install`, чтобы заменить установленную сборку из tap. Если установлена формула `vite-plus`, сначала выполните `brew uninstall vite-plus`; так сохранятся ваши пользовательские данные.
`brew test` использует временные пользовательские данные и не изменяет конфигурацию оболочки. После этого выполните `vp`, чтобы настроить предварительную сборку для своей учётной записи. При переходе со скриптовой установки [обновите её шимы](#switch-from-the-script-installer), чтобы использовать исполняемый файл Homebrew.

Homebrew загружает из реестра bridge только нативный пакет предварительной сборки и проверяет его контрольную сумму. Номера PR он разрешает в последний опубликованный коммит, который может отличаться от текущей головы PR.
Первый запуск устанавливает подходящие зависимости из bridge. Явно заданный `NPM_CONFIG_REGISTRY` должен указывать на реестр, который также отдаёт эти предварительные пакеты.

Этот селектор действует только для данного tap. Он не изменяет другие формулы Homebrew, и клиент npm во время `brew install` не нужен.
Чтобы проверить изменения самой формулы, сначала проверьте PR в репозитории tap. Задайте `HOMEBREW_NO_AUTO_UPDATE=1` для этих команд, чтобы сохранить это состояние репозитория.

Чтобы вернуться к стабильному выпуску, снимите переопределения, восстановите ветку `main` tap, если вы меняли её состояние, и обновите tap перед переустановкой:

```bash
unset HOMEBREW_VP_PR_VERSION HOMEBREW_NO_AUTO_UPDATE
git -C "$(brew --repository voidzero-dev/vite-plus)" switch main
brew update
brew reinstall voidzero-dev/vite-plus/vp
```
