# Локальный CLI проекта {#project-local-cli}

В отличие от [глобального CLI `vp`](/guide/global-cli), `vite-plus` представляет собой npm-пакет, который содержит локальный CLI проекта `vp` и интегрированный фронтенд-инструментарий. Установите его как зависимость для разработки, если хотите зафиксировать версию инструментария в манифесте и lock-файле проекта или не хотите устанавливать отдельно глобальный CLI.

Локальный пакет включает Vite, Rolldown, Vitest, Oxlint, Oxfmt, tsdown, запуск задач Vite+ и команды менеджеров пакетов. Для его работы требуются уже установленный рантайм Node.js и менеджер пакетов.

## Установка {#install}

В большинстве случаев мы рекомендуем использовать CLI Vite+ для установки в проект или создания нового проекта. Подробнее см. в разделах [Создание проекта](/guide/create) и [Миграция на Vite+](/guide/migrate).

::: code-group

```bash [pnpm]
pnpm dlx --package=vite-plus vp create
```

```bash [npm]
npx --package=vite-plus vp create
```

```bash [Yarn]
yarn dlx --package vite-plus vp create
```

```bash [Bun]
bunx --package vite-plus vp create
```

:::

Запускайте его бинарный файл через менеджер пакетов. Например:

```bash
./node_modules/.bin/vp migrate --help
./node_modules/.bin/vp check
```

В документации для удобства используются команды `vp` без префикса. Без глобального CLI добавляйте к интерактивным командам префикс локального исполнителя бинарных файлов вашего менеджера пакетов, например `pnpm exec`.

### Ручная установка {#manual-installation}

Если вы вручную переносите проект на Vite+, сначала установите следующие dev-зависимости:

```bash
vp install -D vite-plus
```

Необходимо добавить переопределения в настройки вашего пакетного менеджера, чтобы другие пакеты использовали версии Vite+, а именно: указать `vite` как алиас для `@voidzero-dev/vite-plus-core`, подставив `<vite-plus-version>` — установленную версию `vite-plus`, а для `vitest` зафиксировать `<vitest-version>` — версию из состава Vite+, которую показывает `vp toolchain vitest`, чтобы весь проект использовал одну и ту же копию Vitest вместе с `vp test`. Без фиксации версии `vitest` зависимость или пакет workspace может подтянуть другую версию Vitest, отличную от раннера из состава Vite+, из-за чего внутренние компоненты Vitest (моки, `expect`, состояние раннера) окажутся разделены:

::: code-group

```yaml [pnpm-workspace.yaml]
overrides:
  vite@*: npm:@voidzero-dev/vite-plus-core@<vite-plus-version> # Укажите установленную версию vite-plus
  vitest@*: <vitest-version> # Возьмите версию из vp toolchain vitest
```

```json [npm / Bun package.json]
"overrides": {
  "vite": "npm:@voidzero-dev/vite-plus-core@<vite-plus-version>",
  "vitest": "<vitest-version>"
}
```

```json [Yarn package.json]
"resolutions": {
  "vite": "npm:@voidzero-dev/vite-plus-core@<vite-plus-version>",
  "vitest": "<vitest-version>"
}
```

:::

::: details Зачем нужны эти настройки?

Зависимости и плагины могут напрямую импортировать `vite` или `vitest`, даже если ваш собственный код импортирует их из `vite-plus`. Эти переопределения согласуют их зависимости с инструментариями, которые использует Vite+:

- Алиас `vite` направляет такие импорты на основной пакет Vite+. Отдельные экземпляры Vite могут нарушать проверки идентичности во время выполнения: в [issue #1391](https://github.com/voidzero-dev/vite-plus/issues/1391) сообщается, что TanStack Start возвращал ошибки 404 из-за проверки `instanceof`, выполнявшейся между двумя копиями. [PR #2617](https://github.com/voidzero-dev/vite-plus/pull/2617) устраняет эту проблему на стороне CLI, используя один и тот же алиас для общего экземпляра Vite.
- Точная фиксация версии `vitest` гарантирует, что зависимости и `vp test` используют одну и ту же версию Vitest, предотвращая появление отдельных моков, экземпляров `expect` и состояния раннера. В [PR #2365](https://github.com/voidzero-dev/vite-plus/pull/2365) это требование описано для ручной установки.

Поддерживайте алиас основного пакета в соответствии с установленной версией `vite-plus`, а при обновлении обновляйте фиксацию версии Vitest в соответствии с версией, входящей в состав пакета. В [issue #2356](https://github.com/voidzero-dev/vite-plus/issues/2356) описано, как боты для обновления зависимостей могут независимо обновлять эти пакеты, оставляя несовместимые версии установленными одновременно.

:::

## Лучшие практики {#best-practices}

Мы рекомендуем использовать [глобальный CLI](/guide/global-cli) вместе с локальным CLI проекта. Глобальный CLI делает `vp` непосредственно доступным в терминале и передаёт команды разработки, такие как `vp dev`, `vp build` и `vp test`, установленному в проекте пакету `vite-plus`. Это обеспечивает удобный доступ к инструментарию, сохраняя при этом его версию под контролем проекта. При желании можно использовать только локальный CLI проекта.

Для проектов с открытым исходным кодом или любых проектов, над которыми работают несколько участников, мы рекомендуем добавлять в `package.json` скрипты, вызывающие `vp`, независимо от того, используете ли вы оба CLI или только локальный CLI проекта. Внутри скриптов `vp` автоматически разрешается из `node_modules/.bin`:

```json [package.json]
{
  "scripts": {
    "dev": "vp dev",
    "check": "vp check",
    "test": "vp test",
    "build": "vp build"
  }
}
```

После установки зависимостей проекта участники могут запускать эти скрипты через свой менеджер пакетов, например `pnpm run dev` или `npm run dev`, без необходимости устанавливать глобальный CLI.

## Что входит в состав {#what-it-includes}

Локальный CLI проекта можно использовать независимо для:

- [`vp dev`](/guide/dev), [`vp build`](/guide/build) и [`vp preview`](/guide/build) с Vite и Rolldown
- [`vp check`](/guide/check), [`vp lint`](/guide/lint) и [`vp fmt`](/guide/fmt) с Oxc
- [`vp test`](/guide/test) с Vitest
- [`vp pack`](/guide/pack) с tsdown
- [`vp toolchain`](/guide/upgrade#show-the-toolchain) для просмотра версий, входящих в состав локального пакета проекта
- [`vp run`](/guide/run) и кэширования задач между рабочими пространствами
- [команд менеджера пакетов](/guide/install) с использованием рантайма Node.js, уже активного в вашей оболочке
- [`vp create`](/guide/create), [`vp migrate`](/guide/migrate) и команд настройки проекта

Локальный пакет не может управлять установкой Vite+ на уровне машины. Для команд `vp env`, `vp upgrade` и `vp implode` требуется [глобальный CLI](/guide/global-cli). Обновляйте или удаляйте локальную установку только через свой менеджер пакетов.

## Добавление глобального CLI позднее {#add-the-global-cli-later}

Вы можете установить глобальный CLI в любое время, не изменяя зависимость проекта. Такие команды, как `vp dev`, `vp build` и `vp test`, продолжат использовать установленную в проекте версию `vite-plus`.

См. раздел [Использование обоих CLI вместе](/guide/global-cli#use-both-clis-together), посвящённый правилам выбора.
