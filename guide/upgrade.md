# Обновление Vite+ {#upgrading-vite}

Используйте `vp upgrade`, чтобы обновить глобальный бинарный файл `vp`. Чтобы обновить локальный пакет `vite-plus` в проекте, см. раздел [Обновление Vite+](/guide/upgrade-project).

## Обзор {#overview}

Обновление Vite+ состоит из двух частей:

- Глобальная команда `vp`, установленная на вашем компьютере
- [Локальный пакет `vite-plus`](/guide/upgrade-project), используемый конкретным проектом

Вы можете обновлять их независимо друг от друга.

## Просмотр инструментов {#show-the-toolchain}

Выполните `vp toolchain`, чтобы посмотреть компоненты, используемые в текущем каталоге:

```bash
vp toolchain
vp toolchain vite
vp toolchain vite rolldown oxc
vp toolchain --json
```

Если в проекте установлен локальный пакет `vite-plus`, команда использует его. Используйте `--global`, чтобы посмотреть версии из глобального релиза `vp`:

```bash
vp toolchain --global
```

`vp why <package>` показывает граф зависимостей, сформированный пакетным менеджером. Он не может показать код, включённый в `@voidzero-dev/vite-plus-core`. Также он не может показать инструменты, скомпилированные в Vite+. Используйте `vp toolchain`, чтобы посмотреть эти версии и связи между ними.

## Глобальная команда `vp` {#global-vp}

Обновляйте глобальный CLI с помощью указанных команд:

```bash
vp upgrade                        # обновить до последней версии
vp upgrade --check                # проверить наличие обновлений без установки
vp upgrade <version>              # установить указанную версию
vp upgrade --registry <registry>  # использовать пользовательский npm-реестр
```

### Перенос существующей установки в раздельную структуру каталогов {#move-an-existing-install-to-the-split-directory-layout}

Vite+ 0.3.0 — первый релиз с поддержкой раздельной структуры каталогов.
Vite+ 0.2.x и более ранние версии используют единую корневую структуру каталогов для новых установок и обновлений.

`vp upgrade` сохраняет существующую установку по умолчанию в `~/.vite-plus` в Unix или `%USERPROFILE%\.vite-plus` в Windows. Команда обновляет CLI в этом каталоге. Она не переносит установку в раздельные каталоги платформы. Вы можете продолжать использовать существующую структуру.

Чтобы использовать раздельную структуру сейчас, удалите существующую установку. Затем установите Vite+ заново. Выполните `vp implode` в оболочке, использующей текущую установку. Команда удаляет сгенерированный файл окружения и записи в профиле оболочки. Она не удаляет переменные каталогов из текущей оболочки. Перед запуском установщика удалите все переменные каталогов Vite+ из окружения. Среди них могут быть значения из ранее созданного файла окружения для preview-версии. В качестве альтернативы после `vp implode` запустите новую оболочку. Затем запустите установщик в новой оболочке.

::: warning
`vp implode` удаляет все управляемые Vite+ среды выполнения Node.js, глобальные пакеты, конфигурацию и кэши. Сохраните существующую структуру, если не хотите создавать эти данные заново.
:::

```bash
vp implode
unset VP_HOME VP_DATA_DIR VP_BIN_DIR VP_CACHE_DIR
curl -fsSL https://vite.plus | bash
```

На Windows:

```powershell
vp implode
Remove-Item Env:\VP_HOME, Env:\VP_DATA_DIR, Env:\VP_BIN_DIR, Env:\VP_CACHE_DIR -ErrorAction SilentlyContinue
irm https://vite.plus/ps1 | iex
```

Также удалите постоянные определения `VP_HOME`, `VP_DATA_DIR`, `VP_BIN_DIR` и `VP_CACHE_DIR` из профиля оболочки или системного окружения. Новая установка использует `VP_HOME` или полный набор переменных `VP_*_DIR`, если они по-прежнему заданы. `VP_HOME` определяет использование единой корневой структуры каталогов. Если вы устанавливаете Vite+ 0.2.x или более раннюю версию, установщик также использует эту структуру. Установщик выводит соответствующее уведомление.

### Откат {#rollback}

Vite+ сохраняет **3 последние** установленные версии, чтобы вы могли быстро выполнить откат:

```bash
vp upgrade --rollback
```

Старые версии автоматически удаляются после каждого обновления. Текущая активная версия и предыдущая версия сохраняются всегда, поэтому версия для отката никогда не будет удалена.

### Homebrew

Homebrew управляет установленными бинарным файлом и пакетом JavaScript. Обновляйте их с помощью:

```bash
brew upgrade vite-plus
```

`vp upgrade` определяет установки через Homebrew и перенаправляет вас к этой команде, не загружая и не устанавливая другую версию. Это также относится к `--force`, указанию конкретной версии и `--rollback`. Для управления такими установками используйте Homebrew.

`vp upgrade --check` перенаправляет вас к `brew outdated vite-plus`. Автоматические проверки обновлений и уведомления npm для установок через Homebrew отключены.

## Предварительные сборки {#preview-builds}

Некоторые пулреквесты Vite+ публикуют временные пакеты для тестирования ещё до выпуска в npm. Рассматривайте их как nightly- или bleeding-edge-сборки: они полезны, если вы хотите проверить конкретное исправление, протестировать свежее обновление зависимости или убедиться в корректности изменений до следующего релиза. Для повседневной работы рекомендуется использовать опубликованную версию `latest`.

Каждый коммит подходящего пулреквеста публикуется через [registry bridge](https://registry-bridge.viteplus.dev/). Этот мост предоставляет такие сборки как обычные версии npm в формате `0.0.0-commit.<sha>` и проксирует все остальные пакеты в реестр npm. Благодаря этому предварительные сборки устанавливаются с помощью обычных спецификаторов версий, а не изменяемых URL, и те же версии будут корректно использоваться в CI.

Пакеты `vite-plus` и `@voidzero-dev/vite-plus-core` публикуются с одной и той же версией вида `0.0.0-commit.<sha>`. Каждый пулреквест содержит комментарий с точной версией последнего коммита и готовыми командами для установки.

Предварительные сборки можно найти в пулреквестах, которые автоматически обновляют зависимости. Например, просмотрите объединённые пулреквесты с [обновлениями зависимостей](https://github.com/voidzero-dev/vite-plus/pulls?q=is%3Apr+is%3Amerged+upgrade+upstream+dependencies).

Предварительные сборки идентифицируются по номеру пулреквеста или SHA коммита. Они не являются стабильным диапазоном версий, поэтому не рекомендуется оставлять их в долгоживущих ветках, если только сопровождающий проекта не попросит вас об этом.

### Предварительная версия глобальной команды `vp` {#global-vp-preview}

Чтобы установить предварительную сборку глобальной CLI, передайте переменную `VP_PR_VERSION` установщику. В качестве значения можно указать номер пулреквеста или SHA коммита:

```bash
curl -fsSL https://vite.plus | VP_PR_VERSION=<pr-or-sha> bash
```

На Windows:

```powershell
$env:VP_PR_VERSION = "<pr-or-sha>"
irm https://vite.plus/ps1 | iex
Remove-Item Env:\VP_PR_VERSION
```

Установщик использует `registry bridge` (промежуточный механизм для реестра пакетов), чтобы сопоставить указанный ref со сборкой `0.0.0-commit.<sha>`. Эта сборка устанавливается так же, как и другие версии. Выполните `vp toolchain --global`, чтобы посмотреть активную сборку и версии инструментов. После тестирования выполните `vp upgrade --force`, чтобы восстановить опубликованный релиз. Также можно запустить установщик без `VP_PR_VERSION`.
