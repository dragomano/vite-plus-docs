# Окружение {#environment}

`vp env` управляет всей средой JavaScript: одной средой выполнения Node.js и одним выбранным менеджером пакетов. npm, pnpm, Yarn и Bun являются семействами взаимозаменяемых менеджеров пакетов.

## Обзор {#overview}

Управляемый режим включён по умолчанию, поэтому Node.js и настроенные shim-команды менеджеров пакетов разрешаются через Vite+ и выбирают подходящие версии для текущего проекта. При установке с нуля после включения управления средой установщики фиксируют управляемый режим для npm, pnpm, Yarn и Bun.

Если после обновления появляется shim-команда менеджера пакетов, для которой режим ещё не сохранён, при первом интерактивном вызове будет предложено выбрать действие, но только если соответствующий системный бинарный файл уже находится в `PATH`. Для текущего семейства по умолчанию используется управляемый режим; выбор системного инструмента или применение выбора ко всем семействам выполняется явно. Неинтерактивные вызовы используют управляемый режим без сохранения выбора.

Если селектор не указан, большинство команд работают с обоими компонентами. Добавьте `node`, `pm`, `npm`, `pnpm`, `yarn` или `bun`, чтобы ограничить область действия команды. `pm` означает все четыре семейства при выполнении команд просмотра списка и очистки, но при операциях над проектом обозначает единственный выбранный менеджер пакетов.

Версии без указания компонента по-прежнему считаются версиями Node.js для обеспечения совместимости:

```bash
vp env pin 22.0.0               # Только Node.js
vp env pin pnpm@10.18.0         # Только pnpm
vp env pin node@24 pnpm@12      # Оба компонента
vp env pin 22.0.0 pnpm@10.18.0  # Также оба компонента
```

Vite+ сначала проверяет текущий каталог, а затем последовательно поднимается по родительским каталогам. Приоритет имеет ближайший каталог, содержащий поддерживаемое объявление версии. Внутри каждого каталога источники проверяются в следующем порядке:

1. Файл `.node-version`
2. `devEngines.runtime` в `package.json` (согласно [стандарту devEngines](https://docs.npmjs.com/cli/v11/configuring-npm/package-json#devengines))
3. `engines.node` в `package.json`
4. Файл `.nvmrc`

Если ни в одном каталоге не указана версия, Vite+ использует глобальную версию по умолчанию (`vp env default`), а затем — последнюю LTS-версию.

`devEngines.runtime` имеет более высокий приоритет, чем `engines.node`, поскольку определяет требования к среде разработки, тогда как `engines.node` описывает диапазон версий, поддерживаемых для пользователей пакета. Если указанные источники противоречат друг другу, `vp env doctor` выведет предупреждение.

::: tip Использование pnpm с управлением средой выполнения в Vite+
pnpm также может управлять средой выполнения, объявленной в `devEngines.runtime`. Если Node.js одновременно управляется pnpm и Vite+, они могут отдельно загрузить одну и ту же версию или выбрать разные версии, что приведёт к непредсказуемому поведению разных команд.

Если вы хотите, чтобы Vite+ управлял Node.js, начиная с pnpm 11 можно глобально отключить автоматическое управление средой выполнения pnpm с помощью [`runtimeOnFail`](https://pnpm.io/settings/cli#runtimeonfail):

```bash
pnpm config set --global runtimeOnFail ignore
```

Этот параметр также отключает автоматическое управление другими объявленными средами выполнения, включая Bun и Deno. Прежде чем устанавливать его глобально, убедитесь, что ни один из ваших проектов не зависит от такого поведения.
:::

При выборе менеджера пакетов используется следующий приоритет:

1. Явно заданное переопределение в команде
2. `VP_PACKAGE_MANAGER` или переопределение для текущего сеанса оболочки
3. `packageManager` верхнего уровня
4. `devEngines.packageManager`
5. Lock-файл или конфигурация конкретного менеджера
6. Глобальная версия по умолчанию для указанного менеджера пакетов
7. Последняя доступная версия указанной shim-команды

Выбранный менеджер управляет только соответствующими ему shim-командами. Например, pnpm управляет `pnpm` и `pnpx`; при вызове `npm` версия npm определяется независимо. Пары алиасов: `npm`/`npx`, `pnpm`/`pnpx`, `yarn`/`yarnpkg` и `bun`/`bunx`. Если в проекте не задан соответствующий выбор, именованная shim-команда использует настроенную версию по умолчанию, а если она не задана — последнюю доступную версию без запроса подтверждения. Определённая версия кэшируется на один час, а после истечения срока кэша она по-прежнему доступна, если не удаётся подключиться к реестру. Напрямую вызываемая shim-команда npm сохраняет резервный вариант с версией npm, поставляемой вместе с Node.js, тогда как явное указание семейства `npm` в `vp env ...` использует последнюю доступную версию автономного npm.

Новая установка по умолчанию использует раздельную структуру каталогов для платформы. В Unix Vite+ хранит управляемые среды выполнения и связанные с ними файлы в `~/.local/share/vite-plus`. Исполняемые файлы хранятся в каталоге `~/.local/share/vite-plus/bin`, принадлежащем Vite+. В Windows Vite+ использует `%LOCALAPPDATA%\vite-plus\data` для данных и `%LOCALAPPDATA%\vite-plus\bin` для исполняемых файлов. Vite+ не переносит существующую установку из `~/.vite-plus`. `VP_HOME` размещает все категории в одном пользовательском корневом каталоге.

Если вы хотите сохранить такое поведение, выполните:

```bash
vp env on
```

Это включает управляемый режим для обоих компонентов. Их режимы также можно изменять независимо друг от друга, в том числе для одного семейства менеджеров пакетов:

```bash
vp env on node
vp env off pm
vp env off pnpm
vp env on bun
```

Если вы не хотите, чтобы Vite+ в первую очередь управлял Node.js, выполните:

```bash
vp env off
```

Это переключает оба компонента в режим с приоритетом системных инструментов. Vite+ предпочитает системные инструменты, а при их отсутствии использует управляемые установки. Смешанные конфигурации работают совместно: системная shim-команда менеджера пакетов получает версию Node.js, выбранную режимом Node.js.

Использование `pm` задаёт выбранный режим для всех поддерживаемых в настоящее время менеджеров пакетов и заменяет их индивидуальные настройки. Непривязанные к конкретному компоненту команды `on` или `off` делают то же самое, одновременно изменяя режим Node.js. Для семейства, режим которого ещё не задан, выбор остаётся неопределённым до первого использования его shim-команды или выполнения команды `on` / `off`, которая задаёт этот режим.

## Команды {#commands}

### Настройка {#setup}

- `vp env setup` создаёт или обновляет shim-файлы `node`, `npm`, `npx`, `pnpm`, `pnpx`, `yarn`, `yarnpkg`, `bun`, `bunx`, `vpx` и `vpr` в определённом каталоге bin. Он записывает скрипты настройки оболочки в каталог конфигурации.
- `vp env on` / `vp env off` изменяет оба режима; добавьте `node`, `pm`, `npm`, `pnpm`, `yarn` или `bun`, чтобы ограничить область изменения
- `vp env print` выводит настройки PATH для обоих компонентов; добавьте селектор, чтобы вывести настройки только для одного компонента

В PowerShell необходимо выполнить dot-source для сгенерированного сценария настройки в текущей оболочке, прежде чем `vp env use` сможет влиять только на текущую сессию оболочки:

```powershell
. "$env:APPDATA\vite-plus\env.ps1"
```

Если в старой установке Vite+ используется `%USERPROFILE%\.vite-plus`, вместо этого загрузите файл `env.ps1` из этого каталога.

Добавьте эту строку в конец вашего PowerShell-профиля `$PROFILE`, чтобы она автоматически применялась в новых сессиях оболочки. Для этого не требуются повышенные привилегии.

Создайте файл профиля, если он ещё не существует:

```powershell
if (-not (Test-Path $PROFILE)) { New-Item $PROFILE -Force }
```

Откройте файл профиля для редактирования:

```powershell
Invoke-Item $PROFILE
```

Командная строка Windows (`cmd.exe`) не может определить функцию-обёртку, необходимую для того, чтобы `vp env use` мог обновить текущий сеанс оболочки. Вместо этого используйте сгенерированную команду `vp-use.cmd`:

```batch
vp-use 20
node --version
vp-use --unset
```

Эта альтернативная команда требуется только для `vp env use`. Остальные команды `vp env` работают в командной строке Windows без каких-либо изменений. Команда `vp env setup` создаёт `vp-use.cmd` в директории `bin` в Windows.

В CI `vp env use` может выполняться без инициализации оболочки. Он записывает временный файл сеанса Node.js или менеджера пакетов в определённый каталог состояния. Последующие вызовы shim-команд в рамках того же задания используют эти файлы для выбора той же среды.

### Управление {#manage}

- `vp env default` показывает глобальную версию Node.js по умолчанию и версию каждого настроенного менеджера пакетов. Версии без указания компонента задают версию Node.js; спецификации с указанием менеджера, такие как `pnpm@10.18.0`, задают версию по умолчанию для shim-команды этого менеджера, не изменяя версии по умолчанию для Bun, Yarn или npm. `--unset` удаляет все значения по умолчанию, если не указан селектор.
- `vp env pin` показывает или записывает версии, зафиксированные для проекта. Существующие поля `.node-version` и `packageManager` верхнего уровня по-прежнему обновляются для обеспечения совместимости; в противном случае Vite+ записывает соответствующую запись `devEngines`. Используйте `--target node-version`, `--target dev-engines` или `--target package-manager`, чтобы явно выбрать способ фиксации.
- `vp env unpin` по умолчанию удаляет обе действующие фиксации; добавьте селектор, чтобы удалить только одну из них. Объявления с более низким приоритетом не удаляются.
- `vp env use` активирует всю среду проекта. Явно указанные спецификации переопределяют выбранные компоненты; `--unset` удаляет настройки обоих компонентов, если не указан селектор.
- `vp env install` устанавливает всю определённую среду, выбранный компонент или явно указанные спецификации.
- `vp env uninstall` удаляет явно указанные точные версии Node.js или версии менеджеров пакетов с указанием версии.
- `vp env clean` удаляет неиспользуемые установки. Используйте `clean node`, `clean pm` или укажите конкретный менеджер. Текущие версии и настроенные версии по умолчанию сохраняются.
- `vp env exec` запускает команду в определённой среде. Используйте `--node` и `--package-manager`; `--npm` является псевдонимом для `--package-manager npm@…`.
- `vp node` использует определённую среду выполнения Node.js и предоставляет дочерним процессам путь к выбранному менеджеру пакетов.

### Проверка {#inspect}

- `vp env current` показывает текущее разрешённое окружение
- `vp env doctor` выполняет диагностику окружения
- `vp env which` показывает, какой путь к инструменту будет использован
- `vp env list` показывает отдельные разделы для Node.js, npm, pnpm, Yarn и Bun; селекторы ограничивают вывод
- `vp env list-remote` одновременно получает данные из реестров Node.js и всех четырёх менеджеров пакетов; селекторы ограничивают сетевые запросы. `--lts` неявно выбирает Node.js.

## Настройка проекта {#project-setup}

- Закрепите версию проекта с помощью `vp env pin`
- Используйте `vp install`, `vp dev` и `vp build` как обычно
- Позвольте Vite+ автоматически выбрать подходящую среду выполнения для проекта

## Примеры {#examples}

```bash
# Настройка
vp env setup                  # Создать shim-команды для Node.js и менеджеров пакетов
vp env on                     # Управление Node.js и менеджерами пакетов
vp env off pm                 # Использовать только системные менеджеры пакетов
vp env off pnpm               # Использовать только системный pnpm
vp env print                  # Вывести настройки PATH для обоих компонентов

# Управление
vp env pin lts pnpm@10        # Зафиксировать точные версии обоих компонентов проекта
vp env install                # Установить всю определённую среду
vp env default node@24        # Задать глобальную версию Node.js по умолчанию
vp env default pnpm@10        # Задать глобальную версию pnpm по умолчанию
vp env use 20 pnpm@10         # Переопределить оба компонента для текущей оболочки
vp env use --unset pm         # Удалить только переопределение менеджера пакетов для сеанса
vp env clean                  # Удалить неиспользуемые управляемые версии Node.js и менеджеров пакетов

# Проверка
vp env current                # Показать текущее разрешённое окружение
vp env current --json         # Вывести данные в формате JSON для автоматизации
vp env which node             # Показать, какой исполняемый файл node будет использован
vp env which npx              # Показать закреплённый алиас менеджера пакетов, если packageManager совпадает
vp env list                   # Показать все локально установленные компоненты
vp env list node              # Показать только установки Node.js
vp env list-remote --lts      # Показать только версии Node.js с долгосрочной поддержкой (LTS)

# Выполнение
vp env exec --node lts --package-manager pnpm@10 pnpm install
vp env exec node -v           # Использовать режим shim-команд с автоматическим выбором версии
vp node script.js             # Сокращение: запустить сценарий Node.js с разрешённой версией
vp node -e "console.log(1+1)" # Сокращение: передать любой флаг или аргумент node
```

## Вывод JSON {#json-output}

Вывод JSON для `current`, `list` и `list-remote` организован по компонентам. `current --json` возвращает соседние объекты `node` и `package_manager`:

```json
{
  "node": {
    "version": "22.0.0",
    "source": "devEngines.runtime",
    "source_path": "/project/package.json",
    "project_root": "/project",
    "bin_path": "/home/.vite-plus/js_runtime/node/22.0.0/bin/node",
    "installed": true,
    "mode": "managed"
  },
  "package_manager": {
    "name": "pnpm",
    "version": "10.18.0",
    "source": "packageManager",
    "source_path": "/project/package.json",
    "project_root": "/project",
    "bin_paths": {
      "pnpm": "/home/.vite-plus/package_manager/pnpm/10.18.0/pnpm/bin/pnpm",
      "pnpx": "/home/.vite-plus/package_manager/pnpm/10.18.0/pnpm/bin/pnpx"
    },
    "installed": true,
    "mode": "managed"
  }
}
```

`list --json` и `list-remote --json` группируют массивы компонентов:

```json
{
  "node": [],
  "package_managers": {
    "npm": [],
    "pnpm": [],
    "yarn": [],
    "bun": []
  }
}
```

Селекторы исключают невыбранные поля верхнего уровня или семейства менеджеров пакетов. Вывод данных из реестров работает по принципу «всё или ошибка»: если не удаётся выполнить запрос к любому выбранному реестру, Vite+ не выводит частичный результат ни в обычном, ни в JSON-формате.

## Пользовательское зеркало Node.js {#custom-node-js-mirror}

По умолчанию Vite+ загружает Node.js с `https://nodejs.org/dist`. Если вы работаете за корпоративным прокси или вам необходимо использовать внутреннее зеркало (например, Artifactory), задайте переменную окружения `VP_NODE_DIST_MIRROR`:

```bash
# Устанавливаем конкретную версию из пользовательского зеркала
VP_NODE_DIST_MIRROR=https://my-mirror.example.com/nodejs/dist vp env install 22

# Устанавливаем глобальную версию по умолчанию, используя пользовательское зеркало
VP_NODE_DIST_MIRROR=https://my-mirror.example.com/nodejs/dist vp env default lts

# Задаём постоянное значение в профиле оболочки (.bashrc, .zshrc и т. д.)
echo 'export VP_NODE_DIST_MIRROR=https://my-mirror.example.com/nodejs/dist' >> ~/.zshrc
```

## Проверка цифровой подписи Node.js {#node-js-signature-verification}

При установке Node.js из официального дистрибутива `nodejs.org` Vite+ загружает PGP-подписанный файл `SHASUMS256.txt.asc` и проверяет его подпись с помощью встроенного набора открытых ключей разработчиков Node.js, прежде чем доверять каким-либо контрольным суммам. Это защищает от подмены файла `SHASUMS256.txt` вместе с соответствующим вредоносным архивом. После этого всегда выполняется проверка SHA-256 контрольной суммы загруженного архива.

При использовании пользовательских зеркал (`VP_NODE_DIST_MIRROR`), публикующих только обычный файл `SHASUMS256.txt`, Vite+ использует только проверку контрольной суммы. Если зеркало публикует и файл `.asc`, его подпись также проверяется, а недействительная подпись считается критической ошибкой.

Если в будущем проблемы с набором ключей или сертификатами помешают загрузке, можно установить переменную `VP_NODE_SKIP_SIGNATURE_VERIFY`, чтобы временно отключить проверку PGP-подписи. Проверка SHA-256 контрольной суммы при этом всё равно выполняется, а Vite+ выводит предупреждение о том, что проверка подписи была пропущена:

```bash
VP_NODE_SKIP_SIGNATURE_VERIFY=1 vp env install 22
```
