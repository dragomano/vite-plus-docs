# Окружение {#environment}

Команда `vp env` управляет всей средой JavaScript: одной средой выполнения Node.js и одним выбранным менеджером пакетов. npm, pnpm, Yarn и Bun являются семействами взаимозаменяемых менеджеров пакетов. Она относится к [глобальному CLI](/guide/global-cli) и не входит в локальный пакет `vite-plus` проекта.

## Обзор {#overview}

Представляйте окружение проекта как два компонента, выбираемых независимо друг от друга:

- **Node.js** — рантайм, используемый для выполнения JavaScript-инструментов и скриптов. Каждый проект может указать необходимую ему версию Node.js.
- **Менеджер пакетов** устанавливает зависимости проекта и управляет ими. Каждый проект может выбрать npm, pnpm, Yarn или Bun и указать его версию.

Например, проект может использовать Node.js 24 и pnpm 10. Изменение версии Node.js не меняет выбранный менеджер пакетов, а переключение с pnpm на Yarn не меняет версию Node.js. Vite+ определяет оба компонента при запуске команды, поэтому можно переключаться между проектами без необходимости вручную менять используемые инструменты.

Vite+ связывает эти настройки с вашей оболочкой через **шимы** — небольшие запускающие программы с именами `node`, `npm`, `pnpm`, `yarn` и `bun`, а также их алиасы. В управляемом режиме шим определяет и запускает соответствующий инструмент для текущего проекта. Такие команды, как `vp install`, используют выбранный проектом менеджер пакетов; прямой вызов `pnpm` всегда запускает pnpm, даже в проекте, который выбрал другой менеджер.

Управляемый режим включён по умолчанию, поэтому Node.js и настроенные shim-команды менеджеров пакетов разрешаются через Vite+ и выбирают подходящие версии для текущего проекта. При установке с нуля после включения управления средой установщики фиксируют управляемый режим для npm, pnpm, Yarn и Bun.

Используйте `vp env off`, чтобы отключить управляемый режим для Node.js и менеджеров пакетов. Подробнее о режимах окружения и о том, как переключиться на системные инструменты, см. ниже в разделе [Режимы окружения](#environment-modes).

Если селектор не указан, большинство команд работают с обоими компонентами. Добавьте `node`, `pm`, `npm`, `pnpm`, `yarn` или `bun`, чтобы ограничить область действия команды. `pm` означает все четыре семейства при выполнении команд просмотра списка и очистки, но при операциях над проектом обозначает единственный выбранный менеджер пакетов.

Версии без указания компонента по-прежнему считаются версиями Node.js для обеспечения совместимости:

```bash
vp env pin 22.0.0               # Только Node.js
vp env pin pnpm@10.18.0         # Только pnpm
vp env pin node@24 pnpm@12      # Оба компонента
vp env pin 22.0.0 pnpm@10.18.0  # Также оба компонента
```

Используйте `vp env pin`, чтобы сохранить версии проекта, `vp env default` — чтобы задать резервные версии, а `vp env use` — чтобы переопределить версии для текущей оболочки. Выполните `vp env current`, чтобы увидеть определённое окружение.

## Выбор версии Node.js {#node-js-selection}

Чтобы определить версию Node.js для проекта, Vite+ сначала проверяет текущий каталог, а затем поднимается по дереву его родительских каталогов. Используется ближайший каталог с поддерживаемым объявлением. Внутри каждого каталога источники проверяются в следующем порядке:

1. Файл `.node-version`
2. `devEngines.runtime` в `package.json` (согласно [стандарту devEngines](https://docs.npmjs.com/cli/v11/configuring-npm/package-json#devengines))
3. `engines.node` в `package.json`
4. Файл `.nvmrc`

Если ни в одном каталоге не указана версия, Vite+ использует глобальную версию по умолчанию (`vp env default`), а затем — последнюю LTS-версию.

Псевдоним `lts` выбирает последний LTS-выпуск. Псевдоним `latest` выбирает последний стабильный выпуск, LTS или нет, и пропускает предварительные выпуски, например `27.0.0-alpha.0.0.0`. Чтобы использовать предварительный выпуск, укажите его точную версию.

`devEngines.runtime` имеет более высокий приоритет, чем `engines.node`, поскольку определяет требования к среде разработки, тогда как `engines.node` описывает диапазон версий, поддерживаемых для пользователей пакета. Если указанные источники противоречат друг другу, `vp env doctor` выведет предупреждение.

`devEngines.runtime.version` принимает только версии и диапазоны semver, как в npm и pnpm. Псевдонимы вроде `lts/*` и `latest` работают в `.node-version`, `.nvmrc` и аргументах CLI, но не в этом поле. Когда версию Node.js выбирает это поле, псевдоним приводит к ошибке команды при стандартном `onFail` (`error`) или `download`. При `warn` или `ignore` Vite+ пропускает запись и проверяет следующие источники. Если версию выбирает корректный `.node-version` в том же каталоге, псевдоним в этом поле приводит только к предупреждению, и без предупреждения, если его `onFail` равен `ignore`. Чтобы закрепить там текущий LTS-релиз, выполните `vp env pin lts`.

::: tip Использование pnpm с управлением средой выполнения в Vite+
pnpm также может управлять средой выполнения, объявленной в `devEngines.runtime`. Если Node.js одновременно управляется pnpm и Vite+, они могут отдельно загрузить одну и ту же версию или выбрать разные версии, что приведёт к непредсказуемому поведению разных команд.

Если ваш проект использует Vite+ для управления версиями Node.js и pnpm, добавьте следующие настройки в `pnpm-workspace.yaml` проекта (pnpm 11+):

```yaml
runtimeOnFail: ignore
pmOnFail: ignore
```

[`runtimeOnFail`](https://pnpm.io/settings/cli#runtimeonfail) отключает автоматическое управление объявленными средами выполнения со стороны pnpm. [`pmOnFail`](https://pnpm.io/settings/cli#pmonfail) не даёт pnpm переключиться на версию менеджера пакетов, указанную в `package.json`. Закоммитьте эти настройки, чтобы политика была общей для всего проекта.

`runtimeOnFail: ignore` также влияет на другие объявленные среды выполнения, включая Bun и Deno. Если проект полагается на pnpm для управления ими, учитывайте это перед включением данной настройки. Перевод существующего проекта на эту политику может изменить записи о средах выполнения в `pnpm-lock.yaml` при следующей установке; проверьте эти изменения и закоммитьте их вместе с конфигурацией.
:::

## Выбор менеджера пакетов {#package-manager-selection}

При выборе менеджера пакетов используется следующий приоритет:

1. Явно заданное переопределение в команде
2. `VP_PACKAGE_MANAGER`
3. `packageManager` верхнего уровня
4. `devEngines.packageManager`
5. Lock-файл или конфигурация конкретного менеджера
6. Глобальная версия по умолчанию для указанного менеджера пакетов
7. Последняя доступная версия указанной shim-команды (версия `npm`, входящая в состав Node.js)

`VP_PACKAGE_MANAGER` выбирает менеджер пакетов и его версию для таких команд, как `vp install`. Шимы менеджеров пакетов, вызываемые напрямую, игнорируют эту переменную и используют независимые переопределения версий:

| Переменная        | Шимы                        |
| ----------------- | --------------------------- |
| `VP_NPM_VERSION`  | `npm`, `npx`                |
| `VP_PNPM_VERSION` | `pnpm`, `pnpx`, `pn`, `pnx` |
| `VP_YARN_VERSION` | `yarn`, `yarnpkg`           |
| `VP_BUN_VERSION`  | `bun`, `bunx`               |

Эти переменные принимают версию, диапазон версий или npm dist-tag, например `10.18.0`, `10`, `latest` или `latest-10`, и переопределяют версии проекта и версии по умолчанию для соответствующего шима. Они не изменяют менеджер или версию, выбранные командой `vp install`.

`vp env use pnpm@10.20.0` устанавливает `VP_PNPM_VERSION` для текущей оболочки, так же как `vp env use node@22` устанавливает `VP_NODE_VERSION`. У каждого менеджера пакетов есть собственное переопределение, поэтому переключение на Yarn не сбрасывает переопределение для pnpm. `vp env use` не устанавливает и не очищает `VP_PACKAGE_MANAGER`.

Прямые шимы определяют свою версию из соответствующей переменной окружения, затем из соответствующего файла сессии, если оболочка-обёртка недоступна, затем из конфигурации проекта и значения по умолчанию для семейства. `vp env current pnpm` и `vp env which pnpm` позволяют проверить выбор версии этого шима; `vp env current pm` сообщает о менеджере, выбранном для команд vp.

```bash
VP_PACKAGE_MANAGER=pnpm@10.18.0 vp install
VP_PNPM_VERSION=10.20.0 pnpm --version
```

Переопределения применяются в управляемом режиме. Менеджер пакетов также может самостоятельно переключить свою версию после того, как Vite+ запустит его; например, [`pmOnFail`](https://pnpm.io/settings/cli#pmonfail) в pnpm 11+ по умолчанию равен `download` и может переключиться обратно на версию из `package.json`. Чтобы версией pnpm управлял Vite+, установите `pmOnFail: ignore` в `pnpm-workspace.yaml` проекта. В pnpm 10 соответствующая настройка называется `managePackageManagerVersions`.

Выбор версии для проекта применяется только к соответствующим ему шимам. Например, pnpm управляет `pnpm`, `pnpx`, `pn` и `pnx`; при этом вызов `npm` по-прежнему независимо определяет используемую версию npm. Если для проекта не задан соответствующий выбор, именованный шим использует настроенную версию по умолчанию, а при её отсутствии — последнюю доступную версию без запроса подтверждения. Шим npm использует встроенный в Node.js npm в качестве запасного варианта. `vp env use npm` выбирает последнюю версию отдельного npm для текущей оболочки, если для проекта или глобально не настроена версия по умолчанию.

Спецификации менеджеров пакетов обрабатываются в порядке npm: сначала точная версия, затем диапазон semver, затем dist-tag. `default` является псевдонимом `latest`, кроме случая npm, где он выбирает npm из `PATH`.

::: details Кэширование dist-тегов
При разрешении dist-тега менеджера пакетов, например `latest` или `latest-10`, включая переход именованного шима на последний выпуск, разрешённая версия кэшируется на один час. Кэш с истёкшим сроком действия остаётся доступным, если до реестра не удаётся достучаться. Реестры, отличные от `https://registry.npmjs.org`, у которых в `.npmrc` заданы учётные данные, запрашиваются при каждом разрешении, поскольку их ответы могут различаться для разных пользователей.
:::

`pn` запускает тот же управляемый бинарный файл, что и `pnpm`, а `pnx` — тот же управляемый бинарный файл, что и `pnpx` (`pnpm dlx`). Эти алиасы также работают с управляемыми версиями pnpm старше v11.

## Режимы окружения {#environment-modes}

Управляемый режим включён по умолчанию, поэтому Node.js и настроенные шимы менеджеров пакетов определяют версии через Vite+ и выбирают подходящие версии для текущего проекта. После включения пользователем управления окружением новые установщики включают управляемый режим для npm, pnpm, Yarn и Bun.

Чтобы включить управляемый режим, выполните:

```bash
vp env on
```

Это включает управляемый режим для обоих компонентов. Их режимы также можно изменять независимо друг от друга, в том числе для одного семейства менеджеров пакетов:

```bash
vp env on node
vp env off pm
vp env off pnpm
vp env on bun
```

Если вы не хотите, чтобы Vite+ в первую очередь управлял Node.js, выполните:

```bash
vp env off
```

Это переключает оба компонента в режим приоритета системных инструментов. Vite+ предпочитает системные инструменты и при необходимости использует управляемые установки в качестве запасного варианта. Смешанные конфигурации комбинируются: средства запуска менеджеров пакетов, которые находят Node.js через `PATH`, получают среду выполнения, выбранную режимом Node.js.

Использование `pm` сохраняет выбранный режим для всех поддерживаемых в данный момент менеджеров пакетов и заменяет их индивидуальные настройки. `on` или `off` без указания области действия делает то же самое, одновременно изменяя режим Node.js.

## Команды {#commands}

### Настройка {#setup}

- `vp env setup` создаёт шимы инструментов и записывает скрипты настройки оболочки.
- `vp env setup --refresh` заново создаёт шимы Vite+ и генерирует скрипты настройки оболочки на основе сохранённых параметров.
- `vp env on` / `vp env off` переключает режимы между управляемым Vite+ и приоритетом системных инструментов; добавьте `node`, `pm`, `npm`, `pnpm`, `yarn` или `bun`, чтобы ограничить изменение соответствующим компонентом.
- `vp env print` выводит настройку `PATH` для обоих компонентов; добавьте селектор, чтобы вывести настройку только для одного из них.

После обновления настройка автоматически обновляется. После этого откройте новый терминал или повторно загрузите скрипт настройки оболочки.

В PowerShell необходимо выполнить dot-source для сгенерированного сценария настройки в текущей оболочке, прежде чем `vp env use` сможет влиять только на текущую сессию оболочки:

```powershell
. "$env:APPDATA\vite-plus\env.ps1"
```

Если в старой установке Vite+ используется `%USERPROFILE%\.vite-plus`, вместо этого загрузите файл `env.ps1` из этого каталога.

Добавьте эту строку в конец вашего PowerShell-профиля `$PROFILE`, чтобы она автоматически применялась в новых сессиях оболочки. Для этого не требуются повышенные привилегии.

Создайте файл профиля, если он ещё не существует:

```powershell
if (-not (Test-Path $PROFILE)) { New-Item $PROFILE -Force }
```

Откройте файл профиля для редактирования:

```powershell
Invoke-Item $PROFILE
```

Командная строка Windows (`cmd.exe`) не может определить функцию-обёртку, необходимую для того, чтобы `vp env use` мог обновить текущий сеанс оболочки. Вместо этого используйте сгенерированную команду `vp-use.cmd`:

```batch
vp-use 20
node --version
vp-use --unset
```

Эта альтернативная команда требуется только для `vp env use`. Остальные команды `vp env` работают в командной строке Windows без каких-либо изменений. Команда `vp env setup` создаёт `vp-use.cmd` в директории `bin` в Windows.

В CI `vp env use` может выполняться без инициализации оболочки. Команда записывает временный файл сессии для каждого рантайма или менеджера пакетов в определённый каталог состояния, например `.session-node-version` или `.session-pnpm-version`. Последующие вызовы шимов в рамках той же задачи используют эти файлы для определения той же среды.

#### Автодополнение оболочки {#shell-completion}

Глобальный CLI поддерживает автодополнение по Tab в Bash, Zsh, Fish, Nushell и PowerShell. Выполните `vp env setup` и следуйте выведенным инструкциям по настройке оболочки, чтобы включить его. Нажимайте Tab, чтобы дополнять команды, а после `vp run` и `vpr` — названия задач проекта.

- **Zsh**: если оболочка ещё не инициализировала автодополнение, выполните `autoload -Uz compinit; compinit` перед загрузкой сценария настройки.
- **Nushell**: для автодополнения требуется `fish` в `PATH`. Используйте Nushell 0.112.1 или новее; см. [Версия Nushell](/guide/global-cli#nushell-version).

### Управление {#manage}

- `vp env default` показывает глобальную версию Node.js по умолчанию и версию каждого настроенного менеджера пакетов. Версии без указания компонента задают версию Node.js; спецификации с указанием менеджера, такие как `pnpm@10.18.0`, задают версию по умолчанию для shim-команды этого менеджера, не изменяя версии по умолчанию для Bun, Yarn или npm. `--unset` удаляет все значения по умолчанию, если не указан селектор.
- Спецификации `vp env default <lts|latest>` и dist-теги менеджеров пакетов, например `pnpm@latest` или `pnpm@latest-10`, заново разрешаются при каждом использовании, поэтому версия по умолчанию следует за тегом, включая новые мажорные версии для `latest`. Остальные версии и диапазоны, например `24` или `pnpm@10`, при установке разрешаются в конкретную версию.
- `vp env pin` показывает или записывает закреплённые версии проекта. Закрепление Node.js использует текущий каталог. Закрепление менеджера пакетов использует `package.json` в корне рабочего пространства, а за пределами рабочего пространства — `package.json` текущего проекта. Закрепление обоих компонентов может обновить два разных файла.

  Существующий файл `.node-version` и поле `packageManager` верхнего уровня по-прежнему обновляются для обеспечения совместимости. Существующий `.nvmrc` обновляется, если он является фактическим источником версии Node.js в текущем каталоге. Его комментарии и другое содержимое, не относящееся к версии, сохраняются. В противном случае Vite+ записывает соответствующую запись `devEngines`.

  Используйте `--target node-version`, `--target nvmrc`, `--target dev-engines` или `--target package-manager`, чтобы явно выбрать источник закрепления. Это не меняет каталог проекта. Для менеджера пакетов вывод показывает путь к файлу относительно текущего рабочего каталога и обновлённое поле либо целевое поле перед запросом на перезапись существующего файла. Закрепление во вложенном каталоге не изменяет унаследованный `.nvmrc`.

- `vp env unpin` (псевдоним для `vp env pin --unpin`) по умолчанию удаляет обе действующие фиксации; добавьте селектор, чтобы удалить только одну из них. Удаление версии Node.js использует текущий каталог. Удаление менеджера пакетов использует манифест в корне рабочего пространства, а за пределами рабочего пространства — манифест текущего проекта. `--target` выбирает источник закрепления в этих пределах. Вывод указывает удалённое поле менеджера пакетов либо поля, которые были проверены, если подходящей фиксации не найдено. Объявления с более низким приоритетом не удаляются.
- `vp env use` активирует всю среду проекта. Явно указанные спецификации переопределяют выбранные компоненты; `--unset` удаляет настройки обоих компонентов, если не указан селектор.
- `vp env install` устанавливает всю определённую среду, выбранный компонент или явно указанные спецификации.
- `vp env uninstall` удаляет версию Node.js, разрешённую из явно указанной версии или селектора, например `22` или `lts`. Для менеджеров пакетов требуется полная точная версия, например `pnpm@10.18.0`.
- `vp env clean` удаляет неиспользуемые установки. Используйте `clean node`, `clean pm` или укажите конкретный менеджер. Текущие версии и настроенные версии по умолчанию сохраняются.
- `vp env exec` запускает команду в определённой среде. Используйте `--node` и `--package-manager`; `--npm` является псевдонимом для `--package-manager npm@…`.
- `vp node` использует определённую среду выполнения Node.js и предоставляет дочерним процессам путь к выбранному менеджеру пакетов. Он запускает Node.js как есть, поэтому файлы TypeScript получают только удаление типов средствами Node.js; [`vpx <file>`](/guide/vpx#running-scripts) запускает их в той же среде выполнения с полной поддержкой TypeScript.

### Проверка {#inspect}

- `vp env current` показывает текущее разрешённое окружение
- `vp env doctor` выполняет диагностику окружения. Добавьте `node`, чтобы сосредоточиться на Node.js, `pm` — для всех менеджеров пакетов или `npm`, `pnpm`, `yarn` либо `bun` для конкретного менеджера пакетов.
- `vp env which` показывает, какой путь к инструменту будет использован
- `vp env list` показывает отдельные разделы для Node.js, npm, pnpm, Yarn и Bun; селекторы ограничивают вывод
- `vp env list-remote` одновременно получает данные из реестров Node.js и всех четырёх менеджеров пакетов; селекторы ограничивают сетевые запросы. `--lts` неявно выбирает Node.js.

## Настройка проекта {#project-setup}

- Закрепите версию проекта с помощью `vp env pin`
- Используйте `vp install`, `vp dev` и `vp build` как обычно
- Позвольте Vite+ автоматически выбрать подходящую среду выполнения для проекта

## Примеры {#examples}

```bash
# Настройка
vp env setup                  # Создать shim-команды для Node.js и менеджеров пакетов
vp env on                     # Управление Node.js и менеджерами пакетов
vp env off pm                 # Использовать только системные менеджеры пакетов
vp env off pnpm               # Использовать только системный pnpm
vp env print                  # Вывести настройки PATH для обоих компонентов

# Управление
vp env pin lts                # Закрепить только Node.js на конкретную версию
vp env pin node@26            # Закрепить Node.js 26 на конкретную версию
vp env pin lts pnpm@10        # Зафиксировать точные версии обоих компонентов проекта
vp env pin pnpm@latest-10     # Закрепить pnpm на версию его dist-тега latest-10
vp env install                # Установить всю определённую среду
vp env use 20 pnpm@10         # Переопределить оба компонента для текущей оболочки
vp env use --unset pnpm       # Удалить только сессионную версию pnpm
vp env use --unset pm         # Удалить все сессионные версии менеджеров пакетов

# Управление (глобальное)
vp env default lts            # Всегда использовать последний LTS, включая новые мажорные версии
vp env default node@24        # Закрепить версию Node.js по умолчанию
vp env default pnpm@10        # Закрепить версию pnpm по умолчанию
vp env clean                  # Удалить неиспользуемые управляемые версии Node.js и менеджеров пакетов

# Проверка
vp env current                # Показать текущее разрешённое окружение
vp env current --json         # Вывести данные в формате JSON для автоматизации
vp env which node             # Показать, какой исполняемый файл node будет использован
vp env which npx              # Показать закреплённый алиас менеджера пакетов, если packageManager совпадает
vp env list                   # Показать все локально установленные компоненты
vp env list node              # Показать только установки Node.js
vp env list-remote --lts      # Показать только версии Node.js с долгосрочной поддержкой (LTS)

# Выполнение
vp env exec --node lts --package-manager pnpm@10 pnpm install
vp env exec node -v           # Использовать режим shim-команд с автоматическим выбором версии
vp node script.js             # Сокращение: запустить сценарий Node.js с разрешённой версией
vp node -e "console.log(1+1)" # Сокращение: передать любой флаг или аргумент node
```

    "bin_paths": {
      "pnpm": "/home/.local/share/vite-plus/package_manager/pnpm/10.18.0/pnpm/bin/pnpm",

`list --json` и `list-remote --json` группируют массивы компонентов:

    "npm": [],
    "pnpm": [],

Селекторы исключают невыбранные поля верхнего уровня или семейства менеджеров пакетов. Вывод данных из реестров работает по принципу «всё или ошибка»: если не удаётся выполнить запрос к любому выбранному реестру, Vite+ не выводит частичный результат ни в обычном, ни в JSON-формате.

## Пользовательское зеркало Node.js {#custom-node-js-mirror}

Задайте `VP_NODE_DIST_MIRROR`, чтобы использовать зеркало для поиска версий Node.js и их загрузки. URL по умолчанию зависит от платформы.

- macOS, Windows и glibc Linux используют `https://nodejs.org/dist`.
- musl Linux использует `https://unofficial-builds.nodejs.org/download/release`.

```bash
# Устанавливаем конкретную версию из пользовательского зеркала
VP_NODE_DIST_MIRROR=https://my-mirror.example.com/nodejs/dist vp env install 22

# Устанавливаем глобальную версию по умолчанию, используя пользовательское зеркало
VP_NODE_DIST_MIRROR=https://my-mirror.example.com/nodejs/dist vp env default lts

# Задаём постоянное значение в профиле оболочки (.bashrc, .zshrc и т. д.)
echo 'export VP_NODE_DIST_MIRROR=https://my-mirror.example.com/nodejs/dist' >> ~/.zshrc
```

Для правил брандмауэра см. [Сетевые узлы](/guide/global-cli#network-hosts).

## Проверка цифровой подписи Node.js {#node-js-signature-verification}

При установке Node.js из официального дистрибутива `nodejs.org` Vite+ загружает PGP-подписанный файл `SHASUMS256.txt.asc` и проверяет его подпись с помощью встроенного набора открытых ключей разработчиков Node.js, прежде чем доверять каким-либо контрольным суммам. Это защищает от подмены файла `SHASUMS256.txt` вместе с соответствующим вредоносным архивом. После этого всегда выполняется проверка SHA-256 контрольной суммы загруженного архива.

При использовании пользовательских зеркал (`VP_NODE_DIST_MIRROR`), публикующих только обычный файл `SHASUMS256.txt`, Vite+ использует только проверку контрольной суммы. Если зеркало публикует и файл `.asc`, его подпись также проверяется, а недействительная подпись считается критической ошибкой.

Если в будущем проблемы с набором ключей или сертификатами помешают загрузке, можно установить переменную `VP_NODE_SKIP_SIGNATURE_VERIFY`, чтобы временно отключить проверку PGP-подписи. Проверка SHA-256 контрольной суммы при этом всё равно выполняется, а Vite+ выводит предупреждение о том, что проверка подписи была пропущена:

```bash
VP_NODE_SKIP_SIGNATURE_VERIFY=1 vp env install 22
```

## Замена nvm или fnm {#replacing-nvm-or-fnm}

`vp env` может заменить [nvm](https://github.com/nvm-sh/nvm) и [fnm](https://github.com/Schniz/fnm) для управления версиями Node.js. Он читает те же файлы версий, поэтому существующим проектам не нужны изменения. Команды `vp env` сами не запускают Node.js, поэтому проекты со старыми выпусками, такими как Node.js 16 или 18, тоже работают.

### Сходства между nvm или fnm и Vite+

- Файлы `.nvmrc` и `.node-version` работают как есть. Vite+ также читает `engines.node` и `devEngines.runtime` из `package.json`. Порядок этих источников см. в разделе [Выбор версии Node.js](#node-js-selection).
- Файл `.nvmrc` может содержать точную версию вроде `18.20.8` или `v18.20.8`, мажорную версию вроде `18`, LTS-псевдоним вроде `lts/*` или `lts/hydrogen`, либо `node` для последнего выпуска. Vite+ игнорирует `system`, `default` и `iojs`, а затем проверяет следующий источник.
- Вам не нужен хук на смену каталога, например `fnm env --use-on-cd` или скрипт автопереключения nvm. Шимы `node`, `npm` и `npx` выбирают версию для текущего каталога при каждом запуске. Редактор или скрипт получает ту же версию, если каталог шимов есть в `PATH`.
- Когда шиму нужна ещё не установленная версия, Vite+ устанавливает её. Чтобы установить версию заранее, используйте `vp env install`.

### Эквиваленты команд

| Задача                                 | nvm                       | fnm                               | Vite+                               |
| -------------------------------------- | ------------------------- | --------------------------------- | ----------------------------------- |
| Установить версию                      | `nvm install 18`          | `fnm install 18`                  | `vp env install 18`                 |
| Использовать версию в текущей оболочке | `nvm use 18`              | `fnm use 18`                      | `vp env use 18`                     |
| Задать версию по умолчанию             | `nvm alias default 18`    | `fnm default 18`                  | `vp env default 18`                 |
| Закрепить версию проекта               | Изменить `.nvmrc`         | Изменить `.node-version`          | `vp env pin 18`                     |
| Показать текущую версию                | `nvm current`             | `fnm current`                     | `vp env current`                    |
| Показать установленные версии          | `nvm ls`                  | `fnm list`                        | `vp env list node`                  |
| Показать доступные версии              | `nvm ls-remote`           | `fnm list-remote`                 | `vp env list-remote node`           |
| Выполнить команду с версией            | `nvm exec 18 node app.js` | `fnm exec --using=18 node app.js` | `vp env exec --node 18 node app.js` |
| Показать путь к `node`                 | `nvm which current`       |                                   | `vp env which node`                 |
| Удалить версию                         | `nvm uninstall 16.20.2`   | `fnm uninstall 16.20.2`           | `vp env uninstall 16.20.2`          |

`vp env use` меняет только текущую оболочку, и для этого нужна настройка оболочки из `vp env setup`. В командной строке Windows используйте `vp-use`. См. [Настройка](#setup).

`vp env pin` обновляет существующий файл `.nvmrc` или `.node-version`. Другие цели закрепления см. в разделе [Управление](#manage).

### Переход с nvm или fnm

1. Установите глобальный CLI Vite+. См. [Установка `vp` глобально](/guide/#install-vp-globally).
2. Убедитесь, что Vite+ управляет Node.js:

   ```bash
   vp env on node
   ```

3. Удалите из профиля оболочки строки, которые загружают nvm или fnm, например из `~/.zshrc`, `~/.bashrc` или `$PROFILE` в PowerShell. Эти строки ставят `node` из nvm или fnm перед шимами Vite+ в `PATH`. Например:

   ```bash
   # nvm
   export NVM_DIR="$HOME/.nvm"
   [ -s "$NVM_DIR/nvm.sh" ] && \. "$NVM_DIR/nvm.sh"

   # fnm
   eval "$(fnm env --use-on-cd)"
   ```

4. Откройте новый терминал и выполните `vp env doctor node`. В разделе `PATH` строка `node` должна показывать шим Vite+. Предупреждение вроде `node ~/.nvm/... (not vp shim)` означает, что другой `node` всё ещё стоит раньше.
5. В каждом проекте выполните `node -v`, чтобы проверить выбранную версию.
6. Установите нужные глобальные инструменты командной строки заново с помощью [`vp install -g`](/guide/package-management/global-packages). Пакеты, установленные через `npm install -g` под nvm или fnm, остаются в каталогах этих инструментов.
7. После проверки проектов можете удалить nvm или fnm.

### Старые выпуски Node.js

`vp env` может установить выпуск Node.js, если проект Node.js публикует бинарный файл для вашей операционной системы и архитектуры процессора.

У менеджеров пакетов и других запускаемых вами инструментов остаются собственные требования к Node.js.
